# Project Structure

Understanding the files and directories created by excel-to-sql.

## Initial Project Structure

When you run `excel-to-sql init`, it creates a standard project structure:

```bash
my-project/
├── data/
│   └── database.db
├── config/
│   └── mappings.json
├── imports/
│   └── .excel-to-sql/
│       └── backups/
└── exports/
```

## Directory Breakdown

### data/

Contains the SQLite database file.

**Location:** `data/database.db`

**Purpose:** Stores all imported data in SQLite format.

**Structure:**
- One database file (can be opened with any SQLite client)
- Multiple tables (one per type configuration)
- Metadata tables for import history

**Example:**
```bash
# Open database with SQLite CLI
sqlite3 data/database.db

# List tables
.tables

# Query data
SELECT * FROM products LIMIT 10;
```

<Callout type="info">
  **Tip**: Use [DB Browser for SQLite](https://sqlitebrowser.org/) for a graphical interface to explore your database.
</Callout>

### config/

Contains configuration files for type mappings.

**Location:** `config/mappings.json`

**Purpose:** Defines how Excel files are imported into database tables.

**Structure:**
```json
{
  "type_name": {
    "target_table": "table_name",
    "primary_key": ["id"],
    "column_mappings": {...},
    "value_mappings": [...],
    "calculated_columns": [...],
    "validation_rules": [...]
  }
}
```

**Key Elements:**

- **target_table**: Database table name
- **primary_key**: Column(s) that uniquely identify rows
- **column_mappings**: Excel column → Database column mapping
- **value_mappings**: Value transformations
- **calculated_columns**: Derived columns
- **validation_rules**: Data validation rules

**Example:**
```json
{
  "products": {
    "target_table": "products",
    "primary_key": ["id"],
    "column_mappings": {
      "Product ID": {"target": "id", "type": "integer"},
      "Name": {"target": "name", "type": "string"},
      "Price": {"target": "price", "type": "float"}
    },
    "value_mappings": [
      {
        "column": "status",
        "mappings": {"1": "Active", "0": "Inactive"}
      }
    ]
  }
}
```

### imports/

Stores original Excel files that have been imported.

**Purpose:** Backup of original files for reference.

**Usage:**
```bash
# Copy file to imports before importing
cp products.xlsx imports/
excel-to-sql import --file imports/products.xlsx --type products
```

<Callout type="warning">
  Files in `imports/` are not automatically managed. You need to manually copy files here if you want to keep them organized.
</Callout>

### exports/

Destination for exported Excel files.

**Purpose:** Store files exported from the database.

**Usage:**
```bash
# Export to exports directory
excel-to-sql export --table products --output exports/products_report.xlsx
```

### .excel-to-sql/

Generated by Auto-Pilot mode (`excel-to-sql magic`).

**Location:** `.excel-to-sql/` (in the data directory)

**Structure:**
```bash
.excel-to-sql/
├── backups/
├── mappings.json
├── analysis.json
└── quality_report.json
```

**Contents:**

- **mappings.json**: Auto-generated type configurations
- **analysis.json**: Pattern detection results
- **quality_report.json**: Data quality analysis
- **backups/**: Automatic backups before modifications

<Callout type="info">
  The `.excel-to-sql/` directory is created in the directory where you run Auto-Pilot, not necessarily in your project root.
</Callout>

## Database Schema

The SQLite database contains several types of tables:

### Data Tables

Tables created for each type configuration:

**Example - Products Table:**
```sql
CREATE TABLE products (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  price REAL,
  status TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Metadata Tables

excel-to-sql creates internal tables for tracking:

#### __excel_to_sql_imports

Tracks all imports:

```sql
CREATE TABLE __excel_to_sql_imports (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type_name TEXT NOT NULL,
  file_name TEXT,
  rows_imported INTEGER,
  content_hash TEXT,
  imported_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  tags TEXT
);
```

**View Import History:**
```bash
excel-to-sql status
```

Or query directly:
```sql
SELECT * FROM __excel_to_sql_imports ORDER BY imported_at DESC;
```

#### __excel_to_sql_metadata

Stores additional metadata:

```sql
CREATE TABLE __excel_to_sql_metadata (
  key TEXT PRIMARY KEY,
  value TEXT,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Common Metadata:**
- `schema_version`: Database schema version
- `last_import`: Most recent import timestamp
- `total_imports`: Total number of imports

## Configuration File Structure

### mappings.json

The core configuration file.

**Full Example:**
```json
{
  "products": {
    "target_table": "products",
    "primary_key": ["id"],
    "column_mappings": {
      "Product ID": {
        "target": "id",
        "type": "integer"
      },
      "Product Name": {
        "target": "name",
        "type": "string"
      },
      "Unit Price": {
        "target": "price",
        "type": "float"
      },
      "In Stock": {
        "target": "in_stock",
        "type": "boolean"
      },
      "Last Updated": {
        "target": "updated_at",
        "type": "date"
      }
    },
    "value_mappings": [
      {
        "column": "status",
        "mappings": {
          "1": "In Stock",
          "0": "Out of Stock",
          "P": "Pending"
        }
      }
    ],
    "calculated_columns": [
      {
        "name": "total_value",
        "expression": "quantity * price"
      }
    ],
    "validation_rules": [
      {
        "column": "id",
        "type": "unique"
      },
      {
        "column": "price",
        "type": "range",
        "min_value": 0,
        "max_value": 1000000
      },
      {
        "column": "email",
        "type": "regex",
        "pattern": "^[^@]+@[^@]+\\.[^@]+$"
      }
    ]
  }
}
```

### Column Mapping Options

Each column mapping supports:

```json
{
  "column_mappings": {
    "Source Column": {
      "target": "target_column_name",
      "type": "string|integer|float|boolean|date",
      "required": true,           // Optional: Fail if null
      "default": "N/A",           // Optional: Default value
      "trim": true,               // Optional: Trim whitespace
      "nullable": true            // Optional: Allow null values
    }
  }
}
```

## Working with the Structure

### Adding New Types

```bash
# Add a new type configuration
excel-to-sql config add --type customers --table customers --pk id

# Edit the configuration
nano config/mappings.json
```

### Managing Multiple Projects

You can have multiple excel-to-sql projects:

```
projects/
├── sales-data/
│   ├── data/
│   ├── config/
│   └── imports/
├── inventory/
│   ├── data/
│   ├── config/
│   └── imports/
└── reports/
    ├── data/
    ├── config/
    └── imports/
```

Switch between projects:
```bash
cd projects/sales-data
excel-to-sql import --file daily.xlsx --type sales
```

### Git Integration

Recommended `.gitignore` for excel-to-sql projects:

```bash
# Database files
data/database.db
data/database.db-shm
data/database.db-wal

# Excel files (optional)
*.xlsx
imports/*.xlsx
exports/*.xlsx

# Auto-Pilot output
.excel-to-sql/

# Python
__pycache__/
*.pyc
.venv/
```

<Callout type="tip">
  **Best Practice**: Commit `config/mappings.json` to version control, but ignore the database and Excel files unless they are sample data.
</Callout>

## File Paths and Locations

### Default Locations

| Component | Default Path | Customizable |
|-----------|--------------|--------------|
| Database | `data/database.db` | Yes (environment variable) |
| Config | `config/mappings.json` | Yes (`--config` flag) |
| Imports | `imports/` | Yes (manual) |
| Exports | `exports/` | Yes (manual) |
| Auto-Pilot | `.excel-to-sql/` | Yes (`--output` flag) |

### Environment Variables

Set environment variables to customize paths:

```bash
# Custom database location
export EXCEL_TO_SQL_DB_PATH=/custom/path/database.db

# Custom config location
export EXCEL_TO_SQL_CONFIG_PATH=/custom/path/mappings.json
```

## Backup Strategy

### Automatic Backups

Auto-Pilot creates automatic backups in `.excel-to-sql/backups/`:

- Rotation: Maximum 5 backups
- Naming: `filename_YYYYMMDD_HHMMSS.xlsx.bak`
- Trigger: Before applying auto-fixes

### Manual Backup

```bash
# Backup database
cp data/database.db data/database.db.backup

# Backup configuration
cp config/mappings.json config/mappings.json.backup

# Backup entire project
tar -czf project_backup.tar.gz my-project/
```

### Restore from Backup

```bash
# Restore database
cp data/database.db.backup data/database.db

# Restore configuration
cp config/mappings.json.backup config/mappings.json
```

## Common Tasks

### Reset Project

```bash
# Remove database and start fresh
rm data/database.db
excel-to-sql init
```

### Export Configuration

```bash
# Export configuration for sharing
cp config/mappings.json ~/backup/mappings_$(date +%Y%m%d).json
```

### Import Configuration

```bash
# Import configuration from another project
cp ~/backup/mappings_20250126.json config/mappings.json
```

### Migrate to New Machine

```bash
# 1. Copy project directory
scp -r my-project/ user@new-machine:/path/to/projects/

# 2. On new machine
cd /path/to/projects/my-project
excel-to-sql status  # Verify everything works
```
