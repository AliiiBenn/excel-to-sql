## Key Concepts Explained

### Type Configuration

A **type configuration** (or just "type") is a reusable blueprint for importing Excel files. It defines:

- Which table to import into
- Column mappings and types
- Primary key(s)
- Value transformations
- Validation rules

**Example:**
```json
{
  "products": {
    "target_table": "products",
    "primary_key": ["id"],
    "column_mappings": {
      "Product ID": {"target": "id", "type": "integer"},
      "Product Name": {"target": "name", "type": "string"}
    }
  }
}
```

### Column Mapping

Column mapping defines how Excel columns are transformed into database columns:

**Source Column** → **Target Column** + **Data Type**

```json
{
  "column_mappings": {
    "Product ID": {"target": "id", "type": "integer"},
    "Price": {"target": "price", "type": "float"},
    "Active": {"target": "active", "type": "boolean"}
  }
}
```

#### Supported Data Types

| Type | Description | SQL Type | Example |
|------|-------------|----------|---------|
| `string` | Text data | TEXT | "Widget A" |
| `integer` | Whole numbers | INTEGER (Int64) | 42 |
| `float` | Decimal numbers | REAL | 19.99 |
| `boolean` | True/False | BOOLEAN (0/1) | 1 |
| `date` | Date/time | TIMESTAMP | "2025-01-26" |

### Value Mapping

Value mappings transform cell values during import:

```json
{
  "value_mappings": [
    {
      "column": "status",
      "mappings": {
        "1": "Active",
        "0": "Inactive",
        "P": "Pending",
        "S": "Shipped"
      }
    }
  ]
}
```

**Use Cases:**
- Code translation (1→Active, 0→Inactive)
- Language translation (ENTRÉE→inbound)
- Category mapping (E→Electronics)

### Primary Keys

Primary keys uniquely identify each row and enable **UPSERT** operations:

```json
{
  "primary_key": ["id"]
}
```

**Composite Keys** (multiple columns):
```json
{
  "primary_key": ["order_id", "product_id"]
}
```

**How UPSERT Works:**
1. Check if a row with the primary key exists
2. If yes: **UPDATE** the row
3. If no: **INSERT** a new row

### Calculated Columns

Create new columns based on SQL expressions:

```json
{
  "calculated_columns": [
    {
      "name": "total",
      "expression": "quantity * price"
    },
    {
      "name": "tax",
      "expression": "total * 0.1"
    }
  ]
}
```

### Validation Rules

Ensure data integrity with validation rules:

```json
{
  "validation_rules": [
    {
      "column": "email",
      "type": "regex",
      "pattern": "^[^@]+@[^@]+\\.[^@]+$"
    },
    {
      "column": "age",
      "type": "range",
      "min_value": 0,
      "max_value": 120
    },
    {
      "column": "id",
      "type": "unique"
    }
  ]
}
```

## Auto-Pilot Concepts

Auto-Pilot mode uses intelligent analysis to generate configuration automatically.

### Pattern Detection

Auto-Pilot detects:

- **Primary Keys**: Columns with unique values
- **Foreign Keys**: Columns referencing other tables
- **Value Mappings**: Columns with repeating code patterns
- **Split Fields**: Redundant status columns to combine
- **Data Types**: Optimal SQL types based on data

### Quality Scoring

Multi-dimensional data quality analysis:

| Dimension | Weight | Description |
|-----------|--------|-------------|
| Completeness | 30% | Percentage of null values |
| Uniqueness | 25% | Duplicate detection |
| Validity | 25% | Type and format checking |
| Consistency | 20% | Value distribution analysis |

**Quality Grades:**
- **A (90-100)**: Excellent quality
- **B (75-89)**: Good quality with minor issues
- **C (60-74)**: Acceptable quality with notable issues
- **D (0-59)**: Poor quality requiring attention

### Recommendations

Auto-Pilot generates prioritized recommendations:

- **HIGH**: Critical issues affecting data integrity
- **MEDIUM**: Quality improvements
- **LOW**: Nice-to-have optimizations

## Data Flow

Understanding the import pipeline:

```mermaid
graph LR
    A[Excel File] --> B[Read & Parse]
    B --> C[Apply Column Mappings]
    C --> D[Apply Value Mappings]
    D --> E[Calculate Columns]
    E --> F[Validate Data]
    F --> G[UPSERT to Database]
    G --> H[Store Metadata]
```

### Import Pipeline Steps

1. **Read & Parse**: Load Excel file using openpyxl
2. **Column Mapping**: Transform column names and types
3. **Value Mapping**: Transform cell values
4. **Calculate Columns**: Create derived columns
5. **Validation**: Check data against rules
6. **UPSERT**: Insert or update database rows
7. **Metadata**: Store import history and tags

## Project Structure

When you run `excel-to-sql init`, it creates:

```
my-project/
├── data/
│   └── database.db          # SQLite database
├── config/
│   └── mappings.json        # Type configurations
├── imports/                 # Original Excel files
├── exports/                 # Exported Excel files
└── .excel-to-sql/          # Auto-Pilot output (optional)
```

### Configuration File Structure

`config/mappings.json` contains all type configurations:

```json
{
  "type_name_1": {
    "target_table": "table1",
    "primary_key": ["id"],
    "column_mappings": {...},
    "value_mappings": [...],
    "calculated_columns": [...],
    "validation_rules": [...]
  },
  "type_name_2": {...}
}
```

## Import History

excel-to-sql tracks all imports with:

- **Timestamp**: When the import occurred
- **Type**: Which type configuration was used
- **Rows**: Number of rows imported
- **File**: Original Excel filename
- **Content Hash**: For change detection

View history:
```bash
excel-to-sql status
```

## Metadata & Tags

Tag your imports for organization:

```python
sdk.import_excel(
    file_path="products.xlsx",
    type_name="products",
    tags=["q1-2025", "verified", "catalog"]
)
```

Tags help you:
- Filter imports by category
- Track data sources
- Manage data versions
- Organize exports

## Incremental Imports

excel-to-sql uses **content hashing** for efficient incremental imports:

1. Calculate hash of Excel file content
2. Compare with last import hash
3. Skip import if content unchanged (unless `--force` is used)

This saves time when re-importing unchanged files.

## Error Handling

### Import Errors

When an error occurs during import:

- **Validation Errors**: Logged but don't stop import
- **Critical Errors**: Stop import and show detailed error message

```bash
excel-to-sql import --file products.xlsx --type products
# → ERROR: Primary key column 'id' not found in Excel file
```

### Recovery

Fix the error and retry:

```bash
# Fix configuration
excel-to-sql config add --type products --table products --pk ID

# Retry import
excel-to-sql import --file products.xlsx --type products
```

## CLI vs SDK

Choose based on your use case:

### CLI (Command-Line Interface)
**Best for:**
- Quick data imports
- Ad-hoc data cleaning
- Interactive workflows
- Scripts and automation

**Example:**
```bash
excel-to-sql import --file data.xlsx --type mytype
```

### Python SDK
**Best for:**
- Programmatic access
- Integration with applications
- Custom data pipelines
- Complex transformations

**Example:**
```python
from excel_to_sql import ExcelToSqlite
sdk = ExcelToSqlite()
result = sdk.import_excel("data.xlsx", "mytype")
```

## Common Patterns

### 1. Periodic Data Imports
```bash
# Cron job to import daily
0 2 * * * excel-to-sql import --file /data/daily.xlsx --type sales
```

### 2. Data Validation Pipeline
```python
sdk = ExcelToSqlite()
result = sdk.import_excel("data.xlsx", "mytype")
if result['validation_errors']:
    send_alert(result['validation_errors'])
```

### 3. Multi-Table Import
```bash
excel-to-sql import --file customers.xlsx --type customers
excel-to-sql import --file orders.xlsx --type orders
excel-to-sql import --file products.xlsx --type products
```
